# 规划讲解

用 [讲解深度与调用路径](references/teaching-depth.md) 把已核验材料拆成知识地图。对每一项先判断是读者前置、主线关键决策，还是可以下钻的实现细节。以用户已明确的重点为准，仅询问会影响主线的未知项。

按「是什么、为什么 → 一条完整路径 → 关键判断与分支 → 选定细节与验证」组织。先让读者能复述一个输入到结果，再展开复杂调用。跨图保留同一请求、值、文件或状态。引入术语时先交代它在当前决策中的职责，精确条件和源码紧贴对应机制。

交付一份提纲，写清读者能做什么、每节的问题与结论、贯穿例子、可追溯证据和一次可预测的变化。提纲应包含一小段读者实际会看到的输入说明，并按首次使用顺序列出关键符号及其含义。重构已有材料时给每个心智模型一个主位置，合并重复说明，把历史留在案例审查记录。
