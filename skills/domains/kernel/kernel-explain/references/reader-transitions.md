# 阅读连续性与执行映射

只在讲解切换观察范围、引入术语或展开线程分工时加载。事实仍以本 Case 的固定源码和数学契约为准。

## 观察范围改变，计算链不能凭空改变

- 在切换前明确当前图省略了什么，例如“只展示系数的使用，不展开系数预测”。
- 用同一个值作锚点，画出连续的完整链，再框选下一张图的观察窗口。写清起点已具备什么输入、跨越哪次调用/子层、终点交付给谁。
- 区分权重或状态名与操作名。例如权重不等于加权归约；先解释操作，再给 Collapse 等专业名。
- 对携入/延迟模式，列出所消费状态的生产时刻、本次生成状态的下一消费者，以及必要等待。模式切换表示不同模型契约时，不画成可任意替换的性能开关。

## 运算类型跟随数据轴

为关键阶段记录：输入/输出 shape → 操作类型 → 被归约的轴 → 实现。

| 类型 | 需要说明 |
| --- | --- |
| elementwise / broadcast | 哪些位置独立计算；系数沿哪一维广播 |
| reduce | 合并哪条轴，输出还保留哪些轴；避免只标“归约” |
| matmul | M/N/K 分别对应什么；算法矩阵乘不等于实现使用 Tensor Core |
| load/store/cast/sync | 单列数据移动、舍入、同步，不冒充计算 FLOP |

复合节点可有多个类型。其子操作沿不同轴归约时，说明顺序和对象；不要把两个归约轴暗示为一次同时归约。特殊函数和编译器未知映射保持独立证据口径。

## 术语先说明理由，再给精确谓词

主路径先用读者能回答的问题，例如“边界中还要插入别的计算吗”“通信是否已接管”“输入和设备是否匹配”。紧邻的展开区保留专业名、精确条件、优先级和 pinned caller。

第一次出现的缩写给出它在此决策中的职责。不能靠删掉资格条件或混合不同版本来简化。读者应能解释一个通过例子和一个回退例子，随后能在代码找到相同判断。

## 从任务逐层放大到线程

在展示层级分工前，先完成“这个 kernel 在做什么”的阅读契约：

1. 给出框架/版本、wrapper 和实际 kernel 名称；“旧融合”“producer”“big_fuse”等相对名称不能代替身份。
2. 画清融合前后哪些操作在同一 launch，哪些仍是后续 kernel。明确中间结果的生产者、存放位置、消费者与合并轴。
3. shape 必须有主人：输入、权重、局部/partial、数学结果与实际写回分别标注。view 或某一路切片不能被误读为输出，数学中间值也不一定对应全局缓冲区。
4. 先解释为什么选择这些 grid 轴、每种拆分增加何种并行机会和何种代价，再画分工。漂亮的 CTA 格子不能代替设计理由。
5. 给默认 workload 的教学理由，并验证参数改变的真实源码策略。若实现或算法路径改变，切换解释并停用旧图；不能只替换 T 标签而保留旧 tile/split/local 数组和文案。

每层分工至少关联一个可核查的收益及边界：连续索引需附 stride 假设，local 复用需给消费者，shared 归约需给同步；不把源码连续访问直接升级为已测合并事务或性能收益。源码若存在未复跑的调用绑定等疑点，保留其状态，不以配置推导冒充运行复现。

按 grid → 选中 CTA → warp → thread/lane → 循环坐标展示包含关系。格子必须有具体任务含义和单位；CTA 数不是 SM 数或同时驻留数。

- 选择一个非零 thread/lane，手算至少两轮坐标，说明所有线程共同覆盖的数据范围。
- 区分线程 local 复用、CTA shared 复用、跨 CTA 重复请求和未知 cache 命中。写出谁生产、谁消费、在哪个同步点后读取。
- 若源码明确，画出 warp 内归约、shared partial 与 CTA 内第二级归约；源码未指定 writer lane 或编译布局时保持未知。
- local 数组下标与映射到的全局输出坐标分开。切换输出 tile 时，不能把全局列号直接写成固定长度 local accumulator 的下标。
- 交互同时更新图、公式、文字、mask/写回职责和来源；检查非零 tile、最后一个 split 和最后一个 thread。结构图可用占位符表示 partial，不填造数值。

## 冷读验收

读者能否：连接前后两图的同一值；说出术语对应的操作与归约轴；解释模式下状态来自哪次调用；不展开专业条件也能理解判断理由；手算选中线程的两轮坐标；指出 local/shared 复用和跨任务重算的区别。技术审查核实这些回答；视觉审查另检查图是否实际帮助读者完成推导。
