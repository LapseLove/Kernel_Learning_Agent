# 技术审查

输入是当前成品、关键主张和来源映射。只查受影响的内容、必要来源和领域交接。核验成品实际表达，包括图、例子、文字和交互变化。

1. 固定审查范围与产物版本。沿真实入口追一个正常例子到结果被消费，核验决策者、状态归属、输入输出、交接和图中每类箭头。
2. 改一个关键条件，核对页面展示的分支、失败、回退或停止。实算受影响的公式，复查受影响的副作用或同步。按工作流路由选择领域核对项；以该对象实际存在的边界为准。
3. 核验核心结论的固定出处与证据等级。区分运行事实、工作流约定、作者报告和本地复现。未知项要清楚，核心结论缺证据时记 unclear。
4. 输出 `Technical: pass|fail|unclear`，记录范围、产物版本、定位、推导或反例、修复与复查。争议先核实 Case 再更新成品。HTML 的视觉结果另记在同一版本。

若采用冷读，把成品和问题交给未见答案的读者。请对方复述设计动机、走一条路径并预测一个条件变化，记录原话、第一次卡住的位置和修改后结果。
