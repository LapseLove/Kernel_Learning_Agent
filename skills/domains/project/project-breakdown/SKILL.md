# 项目拆解

先选读者想完成的一件事，用于确定入口和需要解释的模块。围绕「为什么要有这个项目、谁使用它、一次具体任务怎样完成」组织阅读。

1. 用实际入口和输出验证 README 描述。只画对选中任务有因果作用的组件。每个模块标职责、提供的接口、依赖及所拥有的数据或状态。
2. 选一个请求、命令或样例输入，追到结果交给谁。把配置或发现、执行、产物、人工接手分开。拆解 skill 时核对触发条件，区分 Agent 决策、脚本实际调用与人工审核，核实权限、读写和错误边界。
3. 有两类角色时分别跟一条路径。例如 PR 档案的维护者从固定 checkout 定位候选、核查 diff、更新档案；使用者从模型问题查询候选，再回当前 caller 核实。用一次关键词命中但语义无关的结果检验读者是否会继续核查。
4. 对照一个条件变化和实际结果，例如缺配置、查询命中歧义、权限不足或旧档案。记录哪些行为来自代码、哪些由使用约定保证。
